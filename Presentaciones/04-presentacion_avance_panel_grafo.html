02 · Librerías por versión de framework

Qué capa de librerías se estudia

Capa elegida · variable del análisis

Librerías detectables en el HTML (Wappalyzer)

Lo que cada sitio efectivamente entrega al navegador: Lodash, Swiper, Tailwind, React Router… Se observa sitio por sitio y mes a mes en HTTP Archive, y se cruza con CrUX.

Varía entre sitios con el mismo framework: dos sitios con React 18 cargan conjuntos distintos. Esa variación es la que permite estudiar el impacto de las librerías.

Límite: no ve dependencias empaquetadas dentro del bundle sin huella visible.

Capa de interpretación

Dependencias internas del framework (npm)

Lo que trae cada versión según su package.json (ej. next@15.4 → react, styled-jsx, @swc/helpers). Disponible para toda versión publicada en registry.npmjs.org.

Es constante dentro de cada versión: queda totalmente determinada por framework@versión, por lo que no aporta variación propia para identificar efectos.

Uso: explicar por qué difieren dos versiones una vez observada la diferencia.

Wappalyzer además declara relaciones implies entre tecnologías (Next.js → React): permiten separar lo que trae el framework de lo que agrega cada sitio

03 · Migraciones vistas en el grafo

Migrar a React no reemplaza todas las librerías: conserva la mayoría

Librerías por sitio, promedio de los 27 sitios que migraron de jQuery a React
Ejemplo: www.chase.com (migró en 2025)
Cómo se clasifica cada librería que llega

Framework: React y lo que Wappalyzer declara que viene con él (Next.js trae React). Ecosistema React: librerías que requieren React (MUI, React Router) o que los sitios con React usan al menos el doble que el resto. Propias: decisiones del sitio sin relación con React.

Antes = librerías presentes los 3 meses previos al cambio · después = presentes los 3 meses desde el cambio · ambas variantes de jQuery→React, crawl móvil

04 · Cómo encaja en el diseño causal

El grafo aporta covariables previas y ejes de heterogeneidad

Usos

Tratamiento: el efecto estimado es el de migrar tal como lo hacen los sitios, con el paquete de librerías que cambia junto con el framework (efecto total).

Covariables previas: el stack del sitio antes del evento entra al emparejamiento por puntaje de propensión.

Heterogeneidad: stack de origen y proporción de librerías que se conservan como ejes de los bosques causales (H2).

Restricciones y limitaciones

Las librerías que llegan son posteriores al tratamiento: controlar por ellas sesga la estimación (bad control). Sirven para describir mecanismos, no para ajustar el efecto.

Versión no observable para la mayoría de los sitios con React y Vue.

Diferencias de LCP descriptivas: sin control por tráfico, país ni tipo de sitio; el piloto tiene 27 migraciones a React.

Scripts de terceros (analytics, publicidad, tag managers) quedan fuera de esta capa; pueden incorporarse como capa adicional del grafo
